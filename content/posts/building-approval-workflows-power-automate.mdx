# Building Multi-Tier Approval Workflows in Power Automate

Enterprise workflows rarely follow a simple linear path. In real-world organizations, approval processes often need to branch based on departmental thresholds, support mid-process approver injection, and provide clear audit logging.

In this guide, we'll walk through designing a robust, multi-tier approval architecture using **Power Automate**, **Microsoft Dataverse**, and **Adaptive Cards**.

---

## The Challenge

Standard out-of-the-box approval actions in Power Automate present several hurdles when scaling to enterprise requirements:

1. **Static Approvers**: Hardcoded approver emails break when personnel change.
2. **Timeout Limitations**: Default flow runs have a 30-day execution limit.
3. **Audit Visibility**: Standard approval history is siloed and difficult to aggregate for executive reporting.

---

## Architectural Strategy: State Machine Approach

Instead of a single monolithic flow, decouple the process into a **State Machine** pattern:

```
[Request Initiated] 
       ↓
[Validate & Calculate Approvers]
       ↓
[Dispatch Adaptive Card to Teams] ───→ [Approver Acts: Approve/Reject/Vet]
       ↓
[Update Dataverse State Record]
       ↓
[Trigger Next State / Finalize]
```

### Key Benefits

- **Fault Tolerance**: If any stage fails, the process can resume from its current state without restarting.
- **Dynamic Routing**: Additional vetting steps can be injected on-the-fly without editing flow definitions.
- **Omnichannel Interaction**: Approvers can respond directly inside Microsoft Teams, Outlook, or a custom Canvas App.

---

## Implementation Highlights

### 1. Dynamic Approver Matrix in Dataverse
Store approval matrices in a dedicated Dataverse table containing:
- Department / Cost Center
- Value Threshold Range ($0 - $10,000; $10,000 - $50,000, etc.)
- Approver Role / UPN
- Escalation Contact

### 2. Crafting Interactive Adaptive Cards
Adaptive Cards allow approvers to inspect document summaries, attached quotes, and line items directly in Microsoft Teams:

```json
{
  "type": "AdaptiveCard",
  "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
  "version": "1.4",
  "body": [
    {
      "type": "TextBlock",
      "text": "New Purchase Requisition Approval",
      "weight": "Bolder",
      "size": "Medium"
    },
    {
      "type": "FactSet",
      "facts": [
        { "title": "Requested By:", "value": "Operations Team" },
        { "title": "Amount:", "value": "$12,450.00 USD" },
        { "title": "Priority:", "value": "High" }
      ]
    }
  ]
}
```

---

## Key Takeaways

1. Always decouple long-running approval flows with a persistent database state machine.
2. Leverage Microsoft Teams Adaptive Cards for higher user engagement and faster turnaround times.
3. Maintain immutable audit tables for governance and regulatory compliance.
